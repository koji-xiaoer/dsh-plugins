# dsh 0.1.5 升级检查清单

> 评估日期:2026-09-15　评估基线:`0.1.1-rc.1`(当前生产) → `0.1.5-rc.1`(npm `latest`)
> 评估方式:原始 npm 包静态比对 + 补丁 `patch --dry-run` + 隔离实例无头浏览器实测 + A/B 对照

## 1. 必修项(不处理就会坏)

### ⛔ A1. `dsh-model-select-provider-label` 在 0.1.5 下崩溃

**现象**(无头浏览器实测控制台):

```
slot entry crashed in 'conversation.input.model':
Error: cannot get property "remote.session" without inject
```

**后果**:模型选择器回退到内置实现 —— 不再显示「提供商 · 模型」,超阈值提供商折叠/级联面板/三级返回全部失效。

**A/B 实证**:

| 环境 | `msp_*` 元素数 | 模型按钮 class | 按钮文本 |
|---|---|---|---|
| 0.1.1-rc.1(对照) | **6** | `msp_trigger` | `DeepSeek ·` / `DeepSeek-Flash` / `Max` |
| 0.1.5-rc.1 | **0** | `null` | `DeepSeek-Flash` / `Max` |
| 0.1.5-rc.1 + 禁用本插件 | 0(无报错) | `null` | 同上 |

→ 禁用后报错消失,**归因确定为本插件**。

**根因**:0.1.5 的 `modelDirectories.directoryFor()` 内部要访问 `remote.session`,而 cordis 4.0.2 沿调用方 fiber 的 `inject` 声明做校验。本插件用 `ctx.get("modelDirectories")` 取服务、且 `inject` 未声明 `remote` / `remote.session`;内置 `ui-model-selection` 则声明了 `"remote","remote.session"` 并改用 `ctx.inject([...], scope => ...)`。

**位置**:`~/.dsh/profiles/web/plugins/dsh-model-select-provider-label/lib/client.js`
- L548 `function apply(ctx) {` —— 用了 `ctx.get("slots")` / `ctx.get("modelDirectories")`
- L573 `exports.inject = ["slots","locale","sessions","modelDirectories"];`

**修法(二选一)**

```js
// 最小改动:L573 补两个依赖
exports.inject = ["slots", "locale", "sessions", "modelDirectories", "remote", "remote.session"];
```

```js
// 规范改动(L548):用声明式注入替代 ctx.get,让依赖绑定到正确 scope
function apply(ctx) {
  ctx.inject(["slots", "modelDirectories", "sessions", "locale"], (scope) => {
    const slots = scope.slots, models = scope.modelDirectories,
          sessions = scope.sessions, locale = scope.locale;
    localeRef = locale;
    slots.inject("conversation.input.model", () => slots.register({ /* 原样保留 */ }));
  });
}
// 配套:exports.inject 仍需补 "remote","remote.session"
```

**改完的验收**:会话页 `document.querySelectorAll('[class*="msp_"]').length >= 6`,且模型按钮 `className` 为 `msp_trigger`。

### ⛔ A2. 补丁批量失效(8/10)

对**两版原始 npm 包**做 `patch -p0 --forward --dry-run` 的结果:

| 补丁 | 目标文件 | 0.1.5 结果 | 承载的功能 |
|---|---|---|---|
| `dsh-host-apiproxy.patch` | `dsh-host-apiproxy/lib/index.js` | **目标包已删除** | 账单后端 / `session.cost` / 峰谷计价 |
| `dsh-session-schema.patch` | `.../types/api/sessions.schema.js` | **目标包已删除** | `usageOnly` 折叠模式 |
| `dsh-host-schema.patch` | `.../types/api/host.schema.js` | **目标包已删除** | 余额 schema |
| `dsh-fetch-client.patch` | `.../types/fetch/client.js` | **目标包已删除** | 余额 fetch 客户端 |
| `dsh-client-runtime-notify.patch` | `dsh-client-runtime/lib/client.js` | **目标包已删除** | `dshNotify` 通知桥 |
| `dsh-client-connection.patch` | `dsh-client-connection/lib/client.js` | **9/9 hunk 失败** | 余额显示 |
| `dsh-client-ui-conversation.patch` | `dsh-client-ui-conversation/lib/client.js` | **11 hunk 中 7 个失败** | 费用预估 / 账单明细 / 汇率 / 完成提醒 UI |
| `dsh-token-meter.patch` | `dsh-token-meter/lib/index.js` | **2 hunk 中 1 个失败** | `tokenUsageByModel` 投影(注:与插件内已有实现重复) |
| `dsh-client-ui-workspace-share.patch` | `dsh-client-ui-workspace/lib/client.js` | ✅ **干净应用** | 会话分享的会话行 ⋯ 菜单入口 |

> `dsh-client-ui-conversation-sharechip.patch` 的内容已并入 `dsh-client-ui-conversation.patch`,单独重放会报「Reversed (or previously applied)」,属正常。

**关键认知**:`dsh-mods-enhanced` 的客户端 `apply()` 是**空实现**(注释:「客户端 UI 已迁移回 ui-conversation」),`exports.inject = []`,不注册任何 slot。也就是说**费用/账单/余额/完成提醒的 UI 全部住在补丁里**。这几条补丁失效 = 这些功能整体消失。

**处置建议(择一,不要直接重建 host-apiproxy 补丁)**:
- (a) 接受功能缺失,先只升级;
- (b) 把功能从补丁**迁回插件** —— 0.1.5 的扩展点全在(见 §3),迁回后升级不再依赖补丁。这是唯一能止血的长期方案。

## 2. 建议清理项(不阻塞,但属隐患)

### ⚠️ B1. 三个客户端的 `dsh.client.inject` 悬空引用

`package.json` 的 `dsh.client.inject` 仍指向已被删除的 `@deepseek-ai/dsh-client-runtime`:

| 插件 | 当前声明 |
|---|---|
| `dsh-model-select-provider-label` | `["@deepseek-ai/dsh-client-runtime"]` |
| `dsh-session-share` | `["@deepseek-ai/dsh-client-runtime"]` |
| `dsh-mods-enhanced` | `[...,"@deepseek-ai/dsh-client-runtime","@deepseek-ai/dsh-api-remotes", ...]` |

实测:0.1.5 下该依赖在模块图中不存在(0.1.1 下存在),**不阻塞加载**(loader 容忍未解析的 inject),但会在后续版本变成硬失败。清理方式:从 `dsh.client.inject` 移除,或改为新包名 `@deepseek-ai/dsh-client-store`。

### ⚠️ B2. `dsh-mods-enhanced` 客户端空壳归档

其 `lib/client.js` 有 48KB 但 `apply()` 不注册任何 slot(`~/.dsh/profiles/web/node_modules/dsh-mods-enhanced/插件类/dsh-mods-enhanced/lib/client.js`)。宿主半边仅提供 `tokenUsageByModel` 投影 + `agent/status` 完成监听。若走 (b) 方案,此文件就是重建的落点。

### ⚠️ B3. `settings.yaml` 残留键

`ui-conversation.costEstimate` / `ui-conversation.currency` 是补丁引入的键。实测 0.1.5 **容忍未知键**(追加 `ui-bogus-plugin-xyz` 后 `--dump-config` 仍退出码 0),不会阻塞升级,但补丁不重放时这两个键是惰性的。另外 UI 设置页会读写 `ui-conversation.costEstimate`(见 `~/.dsh/settings.yaml`),升级后该面板的开关将不再有效果。

## 6. 复现本次评估的方法

```bash
# 1) 拉取两版原始包做补丁 dry-run(不触碰全局安装)
for V in 0.1.1-rc.1 0.1.5-rc.1; do
  mkdir -p /tmp/dsh-cmp/$V && cd /tmp/dsh-cmp/$V
  for p in dsh-token-meter dsh-host-apiproxy dsh-client-ui-conversation \
           dsh-client-connection dsh-client-runtime dsh-client-ui-workspace; do
    npm pack @deepseek-ai/$p@$V >/dev/null 2>&1 || { echo "FAIL $p@$V(包可能已删除)"; continue; }
    mkdir -p node_modules/@deepseek-ai/$p
    tar xzf *.tgz -C node_modules/@deepseek-ai/$p --strip-components=1 && rm -f *.tgz
  done
done

# 2) 隔离安装目标版本(勿用 npm i -g,会覆盖正在运行的实例)
mkdir -p /tmp/dsh-015 && cd /tmp/dsh-015 && npm init -y
npm install @deepseek-ai/dsh@0.1.5-rc.1 --no-audit --no-fund

# 3) 隔离 HOME 启动(复制 profile,勿共用生产 DSH_HOME)
mkdir -p /tmp/dsh-test/.dsh-home
cp -a ~/.dsh/profiles /tmp/dsh-test/.dsh-home/
cp ~/.dsh/settings.yaml ~/.dsh/.env ~/.dsh/.credentials.yaml /tmp/dsh-test/.dsh-home/
cd /tmp/dsh-015
DSH_HOME=/tmp/dsh-test/.dsh-home node node_modules/@deepseek-ai/dsh/lib/bin.js \
  web --port 3099 --no-open

# 4) 无头浏览器取 DOM/控制台证据(本项目禁用视觉识别,一律以 DOM/计算样式为准)
#    启动日志会打印 ?token=...,用它换取 dsh-auth-* Cookie 后访问
```

**A/B 定位法**(判断某个插件是否为崩溃源):

```bash
cat > /tmp/disable.yml <<'EOF'
- id: dsh-model-select-provider-label
  disabled: true
EOF
# 注意:--patch 是启动器参数,必须放在子命令之前,且不能用 `web` 别名
node .../bin.js --profile web --patch /tmp/disable.yml --port 3097 --no-open
```

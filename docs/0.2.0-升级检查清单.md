# dsh 0.2.0-rc.2 升级预演报告（插件冲突面）

> 评估日期:2026-10-17　基线:`0.1.1-rc.1`(当前生产) → `0.2.0-rc.2`(npm `latest` **且** `next`)
> 方式:rehearse-upgrade.sh(依赖面 diff + 补丁 dry-run)+ 隔离实例(`/tmp/dsh-020rc2`,端口 3099,独立 `DSH_HOME`)+
> 无头浏览器 DOM/控制台取证 + A/B 对照。全程未触碰生产 `~/.dsh` 与 3080 实例。
> 结论:**4 个自制插件里只有 1 个能原样活下来**;10 个补丁 **10/10 全灭**(比 0.1.5 时的 9/10 更糟)。

### 新增机制：peer 兼容性闸门(本次最大变量)

0.2.0 在 `dsh-app-boot` 里新增了插件运行时校验(0.1.1 无此代码):

- 只看插件 `peerDependencies` 里 **`@deepseek-ai/dsh` 或 `@deepseek-ai/dsh-*`** 前缀的条目;
- 用**声明范围**去匹配 **dsh 运行时版本**(0.2.0-rc.2),`includePrerelease: true`;
- 不满足则:**bundle → 整个跳过**;**普通插件行 → 禁用**(不是报错退出);
- 放行方式:精确豁免,记在 `profiles/<name>/compatibility.json`,如

  ```bash
  dsh plugin --profile web allow-version <包名>@<版本> --dsh-version 0.2.0-rc.2 --accept-risk
  ```

- 语义坑:`semver.satisfies("0.2.0-rc.2", "^0.2.0")` = **false**(预发布规则)。要长期修好,peer 必须写成 `^0.2.0-rc.2` 这类含预发布的范围。

## 3.5 两项"界面功能"的处置结论(2026-10-17 追加)

需求:升级后要**有完成提醒**、**有账户余额**。实测结论:

### 余额 —— 0.2.0 已内置,零开发

- 默认 web profile 就挂载了 `deepseek-account` / `llm-deepseek-account` / `ui-settings-account` / `account-controller`;
  设置 → **账户** 页里有余额卡(总余额 + 赠送钱包分项,按币种)
- 数据源是 **DeepSeek 平台登录态**(`AccountController.getBalance` → `deepseekAccount.getBalance`),
  **不是** `DEEPSEEK_API_KEY` 调 `/user/balance`
- 本机现状:`~/.dsh` 下无任何登录态缓存,`settings.yaml`/`.credentials.yaml` 只有 API Key →
  升级后该页会显示「未登录 + 去登录」。**要在浏览器里登录一次 DeepSeek 账号**才会显示数字
- 旧的会话头余额徽标(baln-4 / 4 个补丁)不随升级保留;若以后仍想要"不登录也能在会话头看余额",再迁 baln-4

### 完成提醒 —— 已重写为静态插件 `dsh-session-notify`(已验证可用)

原 `sntf-5` 是**动态插件**(依赖 `harness.handle`,本机已无动态安装通道),其 UI 又依赖两个在 0.2.0 全灭的补丁。
新插件改为静态 bundle:宿主用自有同源路由 `GET /dsnf/state` 代替 `harness.handle`,客户端用 `fetch` 代替 `host.call`。

- 源码:`~/dsh-plugins/插件类/dsh-session-notify/`
- 安装:`DSH_HOME=/tmp/dsh-try bash ~/dsh-plugins/scripts/install-session-notify.sh`(试装)
  / `bash ~/dsh-plugins/scripts/install-session-notify.sh --production`(装生产,自动备份)
- 0.2.0-rc.2 隔离实例实测:
  - `GET /dsnf/state` → `200 {"ok":true,"running":false,"runningCount":0,"completedSeq":0,…}`;`/dsnf/nonexistent` → 404
  - 设置卡渲染:`sntf-card` ×1、2 组开关、3 个音色分段、音量 80% / 增益 100%,控制台零错误
  - **真实会话完成**:页内发一轮真实请求 → 录到提醒卡 `✓会话已完成` + 标题 `✓ 会话已完成 · DeepSeek Harness`(8s 后恢复),
    宿主 `lastCompleted.sessionId` 为该真实 session、`globalSeq` +1 → 证明 0.2.0 的 `agent/status` 仍在正常发事件
- 顺手修了 `sntf-5` 的一个老缺陷:`Number(localStorage.getItem(k))` 在键不存在时得 0,
  新环境会变成"音量 0%"即静音;改为缺键取默认(0.8 / 1.0)

2. **`DSH_HOME=/home/claude/.dsh` 在 harness 的 shell 里是导出状态**,

## 3.6 升级时会悄悄改写 profile 的两个点(重要)

隔离 home 首次 `dsh web` 启动后,该文件被重写(实测 md5 变化 + diff):

| 变化 | 说明 |
|---|---|
| `agent-default-model` 的 config 被替换 | 从用户的 **`openrouter / ox-alpha`**(免费档)改回 `deepseek-official / deepseek-flash / reasoningEffort: max`,即被 `settings.yaml` 的值覆盖 |
| 追加 `ui-settings-general` / `ui-theme` / `llm-deepseek` 行 | 把 settings.yaml 里的对应键**物化**进 profile 层 |

**后果**:若不复核,升级后 `subagent / workflow / ralph` 等派生 Agent 会回落到**付费的 DeepSeek 官方 API** ——
正是本机那条注释想避免的事。**升级后第一件事:检查 `cordis.patch.yml` 尾部 `agent-default-model` 是否仍是 openrouter/ox-alpha。**

### ⚠️ C2. `settings.yaml` 里 `llm-deepseek.models[].inputModalities: [text]` 会关掉原生识图

0.2.0 的 `dsh-llm-deepseek` 默认给 `deepseek-flash` 声明了 `["text","image"]`,但本机 `settings.yaml` 显式写成:

```yaml
llm-deepseek:
  models:
  - id: deepseek-flash
    name: DeepSeek-Flash
    inputModalities:
    - text          # ← 只要不删掉/不加上 image,原生识图就用不上
```

想用"模型自己看图片":把这里改成 `[text, image]`(或整段删掉用默认)。纯文本模型下的兜底只是占位符
`[image omitted because this model accepts text only; attachment sha256:xxxxxxxx]`,不是 OCR。

## 3.7 实战事故复盘(2026-10-17:升级后「Failed to load plugins」)

**现象**:升级到 0.2.0-rc.2 并重启后,界面弹出
`Failed to load plugins / dsh-session-notify / failed to apply loader entry … list slot "settings.general.item"
already has an entry with id "notify" at priority 0 (registered by z5)`。

### 根因链

1. 0.2.0 的 slot 规则:list slot 同 `id` + 同 `priority` **重复注册直接抛错**,整条 loader entry 判失败
   (`dsh-client-ui-slots/lib/index.js:181-185`;遮蔽规则 = **优先级最低者渲染**,见 `entriesOfSlot`)。
2. 插件第一版沿用原补丁的设置卡 cell( `id: "notify"`),且**没写 `priority`**(默认 0)。
3. 「先占位的那个人」(`z5` 是压缩后的模块名)最可能来自**补丁重放**:`upgrade-dsh.sh` 在 `npm i -g` 之后会跑
   `reapply-dsh-mods.sh`,而 0.1.x 的 `dsh-client-ui-conversation.patch` 里就有
   `slots.register({ name: "settings.general.item", id: "notify" … })`;
   `patch -p0 --forward` 打 0.2.0 时**部分 hunk 会带 fuzz 应用成功**(实测:11 个 hunk 中 #1/#8/#9 以 fuzz 2 落到偏移后的位置),
   于是安装包里残留半截老代码。
4. 半打补丁 + 同 id 同优先级 = 上面那条报错。

### 已做的三处修复

| # | 修复 | 位置 | 验证 |
|---|---|---|---|
| 1 | 两处注册改带 **`priority: -1`**,主动遮蔽同 id 的旧实现 | `插件类/dsh-session-notify/lib/client.js` | 复现环境(装一个先注册 `id=notify` @0 的假插件):修复前 `pageerror: already has an entry…` + 卡片消失;修复后 0 报错、`.sntf-card ×1`、旧行被遮蔽(`.fake-notify-row ×0`) |
| 2 | **重复挂载守卫**(客户端 `window.__dshSessionNotifyMounted__`、宿主 `Symbol.for(...)`):同一包被挂两次时第二个实例让位 | 同上 + `lib/index.js` | 故意在 `cordis.patch.yml` 留两条 insert 行:0 报错、卡片 ×1、`GET /dsnf/state` 仍 200、真实会话完成仍能提醒 |
| 3 | **`reapply-dsh-mods.sh` 失败即回滚**:打补丁前先 `cp -a` 快照,任何失败路径都回滚并删 `.rej/.orig` | `dsh-plugins/scripts/reapply-dsh-mods.sh` | 沙盒里对 0.2.0 的 ui-conversation 打 0.1.x 补丁 → 失败后 `md5` 与打之前**完全一致**、无 `.rej` 残留 |

### 升级时的正确姿势

- **跨大版本不要重放补丁**:0.2.0-rc.2 下 10 个补丁 **10/10 打不上**,重放只会留下半打补丁的安装包。
  若 `upgrade-dsh.sh` 仍无条件调用 `reapply`,至少要依赖第 3 条的回滚,别让半截代码留在包里。
- 升级后自查安装包是否被污染:

  ```bash
  G="$(npm root -g)/@deepseek-ai/dsh/node_modules/@deepseek-ai"
  grep -c 'id: "notify"' $G/dsh-client-ui-conversation/lib/client.js          # 期望 0
  grep -cF 'ESTIMATED_PRICES' $G/dsh-client-ui-conversation/lib/client.js     # 期望 0
  find $G -name '*.rej' | head                                                # 期望无输出
  ```

- 装本插件前确认挂载行只有一条:

  ```bash
  grep -c "id: dsh-session-notify" ~/.dsh/profiles/web/cordis.patch.yml       # 期望 1
  ```

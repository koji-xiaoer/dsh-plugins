## 三、关键规则(从本次迁移事故中提炼)

1. **Host 半与 Client 半必须配对在同一个 Package**:`cordis_run update` 到只有 client 半的 Package 会丢失全部 host RPC(本次 cost-6 pkg-9 事故:host absent,费用行/总账单/价格卡全部失效)。修改任一半时,合包重发。
2. **RPC 是 Package-private**:`harness.handle` 的通道只能被同一插件包的 client 调用,**跨插件不能共享**。所以每个需要数据的插件自带 Host 逻辑;插件间不存在运行时服务依赖,只有信息/语义关系(如 tokm-1 投影 ↔ cost-6 原设计消费)。
3. **Slot cell 语义**:`settings.general.item` / `settings.section` 等 list slot 按 `id` 分 cell——同 id 替换,不同 id 并存。与补丁共存期:reused id(`notify`、`cost-estimate`)自动替换补丁 UI;新 id(`billing-v2`)产生并存入口,补丁退役后改回。
4. **密钥一律经 `credentials` 服务**:动态宿主无 `process.env`;`credentials.resolve('XXX')` 会按 继承 env → 托管存储 → `~/.dsh/.env` 顺序解析。缺 key 必须降级而非报错。
5. **浏览器全局需守卫**:`localStorage`/`Audio`/`document`/`FileReader` 不在 Client Builtins 声明内,一律 `typeof X !== 'undefined'` 守卫 + 降级路径。
6. **投影键共享契约**:与宿主同 key 注册必须同 `stateVersion`(否则抛错),注册计数叠加,最后一个卸载才移除。
